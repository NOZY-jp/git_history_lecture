# ハンズオン：自己紹介ドキュメントを作成してPull Requestを送ろう

本ハンズオンでは、GitHub Desktopを利用してブランチの作成からPull Request（PR）の作成までの一連の開発フローを体験する。

---

## 🌿 Step 1: ブランチを作成する
`main` ブランチに直接変更を加えるのではなく、自分専用の作業領域（ブランチ）を作成する。

1. GitHub Desktopの画面上部にある **Current Branch** をクリックする。
2. **`New Branch`** ボタンをクリックする。
3. ブランチ名を **`practice-自分の名前`**（例: `practice-hayashi-nozomi`）としてブランチを作成する。

---

## 📝 Step 2: 自己紹介ファイルを作成する
1. エクスプローラー（Windows）またはFinder（Mac）で、クローンしたリポジトリのフォルダを開く。
2. フォルダ内にある `nozy_jp.md` をコピーし、同じ場所に貼り付ける。
3. コピーしたファイルの名前を **`自分の名前.md`**（例: `hayashi_nozomi.md`）に変更する。
4. 作成したファイルをテキストエディタで開き、自分の情報に書き換えて保存する。

---

## 🚀 Step 3: コミット・プッシュ・Pull Requestの作成
1. **コミット**: GitHub Desktopに戻り、左下のサマリー欄に変更内容（例: `feat: add hayashi_nozomi.md`）を入力し、**`Commit to practice-自分の名前`** をクリックする。
2. **プッシュ**: 画面上部の **`Push origin`** をクリックし、変更をGitHub上に反映させる。
3. **PR作成**: GitHub Desktop上の **`Preview Pull Request`** または **`Create Pull Request`** ボタンをクリックし、ブラウザでGitHubのページを開く。
4. 内容を確認し、**`Create pull request`** をクリックして完了。

---

## ⚠️ 厳守事項：他人のファイルには触らない！
本演習中、**他人が作成したファイルや既存のファイル（`nozy_jp.md`など）の中身は絶対に編集・保存しないこと**。

これを破ると、後述の「コンフリクト（競合）」というエラーが発生し、作業が進行できなくなる可能性が高い。

---

## 💥 コンフリクト（競合）とは？
コンフリクトとは、**「複数人が同じファイルの同じ箇所を同時に編集してしまった状態」** を指す。
この状態に陥ると、Gitは「どちらの変更を優先して保存すべきか」を自動で判断できず、手動での修正（コンフリクト解消）を求めてくる。Git初心者が最も躓きやすいポイントの一つである。

---

## 🚑 トラブルシューティング：コンフリクトが起きてしまったら
もし操作を誤ってコンフリクトを起こしてしまった、あるいはプッシュ時にエラーが出て進めなくなった場合は、Gitの機能で無理に解決しようとせず、以下の「原始的かつ確実な方法」でやり直すこと。

1. **文章の退避**: 自分が書いた自己紹介文（`自分の名前.md`の中身）をコピーし、メモ帳など別のアプリに貼り付けて安全な場所に退避させる。
2. **変更の破棄**: GitHub Desktop上で、自分の行った変更を右クリックして **`Discard changes`** を選択し、リポジトリをまっさらな状態に戻す。
3. **最新状態の取得**: ブランチを `main` に戻し、**`Fetch origin`** (または `Pull origin`) を押して最新の状態を取得する。
4. **やり直し**: 再度 `practice-自分の名前2` のように新しいブランチを作り、退避しておいた文章を使ってStep 2からやり直す。
